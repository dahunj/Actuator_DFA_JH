# FAI / Cosmetic OCAP 추가 및 변경 내용

## 적용 방법

1. 압축을 해제하고 CMAI2100.sln을 Visual Studio 2010에서 엽니다.
2. Debug / Release Win32 설정에서 전체 다시 빌드합니다.
3. 실제 실행 폴더의 System에 포함된 OCAP_Data.ini, ErrorList_KOR.ini, ErrorList_ENG.ini를 적용합니다. 장비에서 별도로 관리한 설정은 먼저 백업하고 비교하십시오.
4. 메인 화면의 OCAP → FAI(치수 불량) / Cosmetic(외관 불량)을 선택합니다.
5. Cosmetic 화면에서 실제 비전 수신 불량 Code와 Name을 등록하고 저장합니다. 실제 외관 코드 목록은 업로드된 OCAP 설정에 없으므로 임의 코드를 넣지 않고 100칸을 비워 두었습니다.

## 동작 기준

원래 FAI와 같이 "모듈 연속 불량 개수"가 아니라 "불량률 조건을 만족한 마가진의 연속 횟수"로 알람을 판단합니다.

- 불량률 = 해당 코드가 발생한 모듈 수 / 마가진 투입 모듈 수 × 100.
- 마가진당 최소 수량 미만, 미완료 이력, 투입 0개, 기준 미달 이력이 나오면 연속 조건이 끊깁니다.
- 설정 불량률과 같은 값도 조건을 만족합니다.
- 공통 조건 3 → 2 → 1 → 측정 Error 순으로 확인하며 한 종류당 첫 알람만 선택합니다. 같은 조건이면 앞 번호 코드가 우선입니다.
- 두 종류에서 동시에 발생하면 FAI를 먼저 표시하고, 알람을 닫은 후 Cosmetic 대기 알람을 표시합니다. 기존 다른 알람이 떠 있으면 대기합니다. 메인 500ms 타이머를 사용합니다.
- 종류별 대기 알람은 1건이며, 알람이 대기 중일 때 해당 종류의 추가 알람 판정으로 상세정보를 덮어쓰지 않습니다. 범용 무제한 알람 큐는 아닙니다.

## 화면 / 코드 설정

FAI와 Cosmetic 모두 기존 레이아웃을 사용합니다. 좌측 10개 / 우측 10개, 20개씩 5페이지, 총 100개입니다. 이전/다음, 빈 코드 이동, 설정/이력 전환, 저장 후 파일 재읽기 검증을 유지합니다.

코드별 연속 마가진 횟수:
- -1: 해당 조건의 공통 연속 횟수 사용.
- 0: 해당 코드의 알람 제외.
- 1~40: 코드별 횟수 사용.

코드별 불량률:
- -1: 해당 조건의 공통 불량률 사용.
- 0 초과~100.000: 코드별 불량률 사용. 소수 3자리.

횟수와 불량률의 -1은 각각 독립적으로 적용합니다. 코드별 개별값을 넣으면 1~3단계 모두 그 개별값을 적용하므로, 같은 조건에서는 기존 우선순위에 따라 3단계 알람이 먼저 선택될 수 있습니다. 공통 횟수의 0은 해당 공통 조건을 사용하지 않는다는 뜻입니다.

FAI와 Cosmetic은 별도의 전역 데이터, 집계 배열, INI 섹션, 로그를 사용합니다. Cosmetic 클래스 멤버와 업무 함수에는 _Cosmetic 접미사를 붙였습니다. 생성자와 MFC 가상 함수/메시지 처리기 이름은 프레임워크 구조에 맞춰 유지했습니다.

## Cosmetic 불량 집계 연결

SequenceMain의 기존 Lot 완료 지점에서 Set_AddMZData_Cosmetic을 호출합니다. 집계는 MES 송신 여부와 관계없이 완료된 메모리 판정 결과에서 수행합니다.

- 모듈 종합 비전 판정 nJudge_I[...,0]이 3 또는 4인 외관 불량을 대상으로 합니다.
- ROS 최종 Good(nJudge_R == 2)은 제외합니다.
- 치수 불량, 바코드/MES/MC 등 특수 불량은 외관 집계에서 제외합니다.
- 각 비전의 판정이 3~6인 결과에서 대표 불량 코드와 추가 코드 20개를 확인합니다.
- 비전 간 또는 추가 코드 간에 같은 모듈/같은 코드가 중복되면 1개로 집계합니다. 서로 다른 등록 코드는 각각 집계합니다.
- 추가 코드 배열 gNG는 원본 장비 구조상 Tray 1 전용이므로 첫 Tray에서만 확인합니다. 대표 코드 배열은 기존 10개 Tray 구조를 사용합니다.
- 실제 통신 코드와 등록 코드의 완전 일치 기준입니다. FAI 전용 7자리 접두어 매칭을 Cosmetic에 임의 적용하지 않았습니다.
- 최종 종합 판정이 치수 NG라면, 그 모듈에 외관 코드도 있더라도 Cosmetic 집계에서는 제외합니다.

측정 Error는 FAI의 F-prefix 방식을 확장해 "F + 등록된 Cosmetic Code"일 때 인식합니다. 예: 등록 코드 SCRATCH에 대해 FSCRATCH를 수신하면 일반 외관 집계와 Error 집계에 각각 1개를 반영합니다. 실제 FSCRATCH 자체가 등록되어 있으면 완전 일치 등록 코드가 우선입니다. 이는 호환용 규칙이며, 외관 측정 Error를 다른 통신 규칙으로 보내는 장비는 그 규칙에 맞춰 OCAP_MatchCode_Cosmetic을 조정해야 합니다. 별도 Error 코드를 보내지 않는 일반 외관 NG는 조건 1~3으로 동작합니다.

## INI 섹션

| 용도 | FAI | Cosmetic |
| --- | --- | --- |
| 공통 조건 | OPTION-FAI | OPTION-COSMETIC |
| 불량 코드 100개 | FAI-CODE | COSMETIC-CODE |
| 불량 이름 100개 | FAI-NAME | COSMETIC-NAME |
| 코드별 연속 횟수 | FAI-MZ-COUNT | COSMETIC-MZ-COUNT |
| 코드별 불량률 | FAI-DEFECTP | COSMETIC-DEFECTP |

공통 키 MZ_COUNT_01~04, DEFECTP_01~04, MZ_MIN_COUNT는 원래 이름 그대로입니다. 이전 파일의 MZ_COUNT, DEFECTP 키도 보존했지만 판정은 원본처럼 _01~04 키를 사용합니다. 코드별 키는 01~99, 100입니다.

첨부 INI의 기존 FAI 설정값은 보존했습니다. Cosmetic 공통값은 FAI 공통값을 초기값으로 복사했으며, 코드/이름은 공란, 코드별 횟수/불량률은 -1로 추가했습니다. 장비에 맞춰 공통값을 조정하십시오.

이전 섹션 OPTION / DATA-CODE / DATA-NAME / DATA-MZ-COUNT / DATA-DEFECTP만 있는 설치 파일을 읽을 때, 대응하는 FAI 신규 섹션이 없으면 그 섹션을 복사합니다. 이미 있는 신규 섹션은 덮어쓰지 않습니다. 구형 파일명 OCAPData.ini의 OCAP_Data.ini 복사 동작도 유지합니다. Cosmetic 초기 섹션은 동봉한 INI로 적용하고, 이후 UI 저장으로 관리합니다.

## 알람과 로그

- FAI: 기존 9181 / 9182 / 9183 / 9184.
- Cosmetic: 9185 / 9186 / 9187 / 9188.
- 한국어/영어 알람 설명과 CAT_ID_MATCH 항목을 함께 추가했습니다.
- ErrorDlg에 Cosmetic 불량명/실제 불량률/실제 적용 기준/횟수를 표시합니다.
- FAI 측정 Error 상세가 개별 설정 대신 공통 설정을 표시하던 부분도 실제 적용값으로 맞췄습니다.
- FAI 로그 경로는 기존 그대로입니다.
- Cosmetic CSV는 LOG\OCAPData_Cosmetic에 별도로 저장합니다.
- Cosmetic 이력의 001~007 / 008~015 / 016~020 열은 원래 FAI 그룹 열을 유지한 코드 번호 범위 소계입니다. 외관 불량 종류를 임의로 분류한 것이 아닙니다. 외관 합계는 100개 코드 발생수 합계이므로 한 모듈에 여러 코드가 있으면 모듈 수보다 클 수 있습니다.
- 누적 마가진 이력은 원본처럼 메모리 50개이며 재시작 시 초기화됩니다. 설정은 INI, 배출 이력은 CSV로 보존합니다.

## 검증 결과와 범위

- 실제 OCAPCosmetic.cpp의 집계/판정 메서드 본문을 추출하여 CString 호환 스텁과 C++98로 컴파일·실행했습니다. 17개 경계/집계 사례 통과.
- 100번째 코드, 기준값과 같은 불량률, 개별 횟수/불량률, -1 공통 조건, 0 제외, 연속 40개, 49→0 이력 순환, 최소 수량/빈 이력/투입 0, Error 알람과 실제 기준값, 잘못된 조건 번호, 카메라 중복, 추가 코드, ROS Good 제외, 치수 NG 제외, F-prefix, 잘못된 Port를 확인했습니다.
- 프로젝트/filters XML, 신규 파일 등록, 다이얼로그/컨트롤 ID, Cosmetic 전역 멤버 참조, 종류별 섹션 분리, 각 100개 설정, 기존 FAI 값 보존, 한국어/영어 알람 등록을 점검했습니다.
- 이 환경에는 Windows / Visual Studio 2010 / MFC 실행 환경이 없어 전체 솔루션 빌드, 실제 창 표시, CSIniFile DLL을 통한 저장 실행, 실제 비전/ROS/모션 장비 연동은 검증하지 못했습니다. 위 테스트는 전체 MFC 빌드나 장비 검증을 대체하지 않습니다.
- 미리 빌드한 EXE는 제공하지 않습니다.
